Functional bugs in web applications are rarely crashes. A total ignores a changed quantity,
a validation rule holds on one path and not another, a value is lost on reload. An automated
tester must reach such states through many interactions and then show that what it found is
real. This thesis presents \emph{Katalyze}, an autonomous exploratory tester for web
applications with a verified-fault evaluation pipeline. It asks how much exploration
structure, lightweight online learning and reliable fault verification each contribute.
A fault counts only if it reproduces twice in fresh browser sessions, is absent from a
control build without that fault, and survives delta-debugging minimisation. No new learning
algorithm is claimed. The contributions are the integrated system, the evaluation method,
and the empirical findings, several of them negative.

The first generation is an action-conditioned dueling double deep Q-network with a reward
from a local language model. In two pre-registered experiments, pretraining on five
applications gave no measurable speed-up on a sixth (median difference 0 interactions, 95\%
interval $[-749, +290]$, too wide to rule a benefit in or out). The network did not reach
the pre-registered bar for learning which action helps in which state (within-label AUROC
0.51). The language model failed as a reward and as a page labeller.

The second generation is a hybrid tester with explicit page abstraction, an archive of
reached states with exact return (Go-Explore), test-design operators, and an optional
learner (a Thompson-sampling bandit or count-based curiosity Q-learning). The evaluation
used eight held-out applications in a pre-registered study of 160 runs and 32 clean-build
controls. The hybrid arms verified 18 and 19 of 24 faults, against 13 for random
exploration, with no false positive. The gap was largest on faults of moderate declared
depth. All four comparisons of time to first fault were inconclusive, and no learning layer
measurably improved on the structure alone.

On WebExplor's six subject applications, measured as the published work measures, the
frozen tester averaged 44.3\% branch coverage, against 55.5\% for WebExplor and 64.2\% for
WebRLED. A post-hoc follow-up found the set of actionable elements to be an important limit:
with custom clickables, Phoenix coverage rose from 49\% to 82--83\%. The evidence suggests
that, for verifying functional faults, a tester's structure and action space matter more
than the learning in it.
