How to read this page. A run is one tester exploring one application: 2,000 browser interactions on the project's own applications, one hour on the external benchmark. It finds a fault when a seeded fault is verified: replayed twice and absent on its control build. Times are interactions to the first verified fault; a run that finds nothing counts as the full budget. Pre-registered evaluations are evidence; development and tuning rounds are not.
